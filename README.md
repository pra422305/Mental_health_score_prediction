# 🧠 Mental Health Score Prediction & Analysis Dashboard

An end-to-end, portfolio-level machine learning project that estimates a continuous
**wellbeing score (0–100)** from lifestyle, behavioral, and demographic survey-style
features, with a full interactive Streamlit dashboard.

> **Disclaimer:** This is an **educational ML project**, not a medical diagnostic
> tool. Predictions are estimates for learning purposes only and must not be
> treated as a clinical diagnosis of depression, anxiety, or any other condition.

---

## 1. Project Overview

The project predicts a self-reported wellbeing score using regression, based on
sleep, stress, social support, lifestyle habits, and work/academic pressure. It
covers the full ML lifecycle: data inspection → EDA → preprocessing → feature
engineering → model comparison → hyperparameter tuning → explainability →
deployment-ready Streamlit app.

## 2. Problem Statement

Given lifestyle and behavioral indicators, predict a continuous mental wellbeing
score and surface which factors are most statistically associated with it —
without making causal or medical claims.

## 3. Objectives

- Build a clean, leakage-free regression pipeline.
- Compare multiple models on consistent metrics (MAE, MSE, RMSE, R²).
- Tune the best-performing model.
- Explain model behavior via feature importance.
- Ship a professional, multi-tab Streamlit dashboard suitable for a placement
  interview demo.

## 4. Dataset Description

`data/dataset.csv` — 2,000 synthetic survey-style records (2,025 rows after
injected duplicates) generated by `src/generate_dataset.py`. A synthetic dataset
was used because no real dataset was supplied and this environment could not
reach Kaggle; the generator encodes plausible, literature-consistent
relationships (e.g., poor sleep + high stress + weak social support → lower
score) plus realistic noise, ~4–5% missingness in four columns, 25 duplicate
rows, and injected outliers, so the pipeline has genuine signal to discover.
**To use your own dataset:** replace `data/dataset.csv` with the same column
names (or update `TARGET`, `NUMERIC_FEATURES`, `CATEGORICAL_FEATURES` in
`src/preprocessing.py` to match your columns), then re-run `src/train.py`.

**Columns:**

| Column | Type | Description |
|---|---|---|
| Age | numeric | Age in years |
| Gender | categorical | Male / Female / Other |
| Employment_Status | categorical | Student / Employed / Unemployed |
| Sleep_Hours | numeric | Average nightly sleep hours |
| Sleep_Quality | numeric | Self-rated sleep quality (1–10) |
| Screen_Time_Hours | numeric | Daily screen time |
| Physical_Activity_Hours | numeric | Weekly exercise hours |
| Social_Interaction_Score | numeric | Self-rated social interaction (0–10) |
| Diet_Quality | numeric | Self-rated diet quality (1–10) |
| Caffeine_Intake_Cups | numeric | Cups of caffeinated drinks/day |
| Work_Study_Hours | numeric | Daily work/study hours |
| Academic_Work_Pressure | numeric | Self-rated pressure (1–10) |
| Financial_Stress | numeric | Self-rated financial stress (1–10) |
| Family_Support_Score | numeric | Self-rated family support (0–10) |
| Stress_Level | numeric | Self-rated stress (1–10) |
| **Mental_Health_Score** | **target** | Continuous wellbeing score (0–100) |

## 5. Engineered Features

- **Lifestyle_Score** — average of diet quality, capped physical activity, and an
  inverse screen-time penalty.
- **Sleep_Efficiency_Score** — combines closeness-to-8-hours sleep with self-rated
  sleep quality.
- **Wellbeing_Support_Score** — average of social interaction and family support.

## 6. EDA

Full EDA (target distribution, histograms, boxplots, correlation heatmap,
feature-vs-target scatterplots, categorical comparisons, missing-value map,
pairplot, outlier counts) is in `notebooks/eda_and_model_training.ipynb`
(pre-executed with real output) and interactively in the Streamlit app's
**Exploratory Data Analysis** tab.

Key finding: no feature leaks the target (no correlation > 0.9) and no two
features are highly collinear (no pair > 0.7).

## 7. ML Algorithms Compared

Linear Regression, Ridge, Lasso, Decision Tree, Random Forest, Gradient
Boosting — all inside a single `ColumnTransformer` + `Pipeline` (impute → scale
numeric / impute → one-hot encode categorical), fit only on the training split
to avoid leakage, evaluated with 5-fold cross-validation.

## 8. Model Evaluation & Best Model

| Model | MAE | RMSE | R² | CV R² (mean) |
|---|---|---|---|---|
| **Ridge Regression** | 5.26 | 6.67 | **0.790** | 0.757 |
| Linear Regression | 5.26 | 6.68 | 0.790 | 0.757 |
| Gradient Boosting | 5.72 | 7.22 | 0.755 | 0.697 |
| Lasso Regression | 6.00 | 7.56 | 0.731 | 0.706 |
| Random Forest | 6.30 | 8.13 | 0.689 | 0.656 |
| Decision Tree | 8.45 | 10.66 | 0.464 | 0.375 |

**Best model: Ridge Regression** (tuned `alpha=5.0` via GridSearchCV), because the
target was generated from a roughly linear combination of features, which linear
models naturally fit best. Tuned test performance: MAE 5.26, RMSE 6.67, **R² 0.790**.

## 9. Feature Importance (top 6, by |coefficient|)

1. Stress_Level
2. Sleep_Quality
3. Social_Interaction_Score
4. Financial_Stress
5. Lifestyle_Score
6. Family_Support_Score

These are statistical associations learned by the model — not medical or causal
claims.

## 10. Streamlit Application

7 tabs: **Home, Dataset Overview, Exploratory Data Analysis, Prediction, Model

## 11. Installation

```bash
git clone <your-repo-url>
cd mental-health-score-prediction
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 12. How to Run Locally

```bash
# (Optional) regenerate the dataset
python3 src/generate_dataset.py

# Train / retrain the model
python3 src/train.py

# Launch the dashboard
streamlit run app.py
```

## 13. Deployment (Streamlit Community Cloud)

1. Push this repository to GitHub (see commands below).
2. Go to [share.streamlit.io](https://share.streamlit.io) → **New app**.
3. Select your repo, branch `main`, and main file path `app.py`.
4. Click **Deploy**. Streamlit Cloud installs `requirements.txt` automatically.
5. Make sure `data/dataset.csv` and `models/model.pkl` are committed to the repo
   (they are small enough to check in directly) so the app doesn't need to
   retrain on first load.

```bash
git init
git add .
git commit -m "Initial commit: Mental Health Score Prediction Dashboard"
git branch -M main
git remote add origin <your-repo-url>
git push -u origin main
```

## 16. Limitations

- Trained on a synthetic dataset (no real Kaggle dataset was supplied); replace
  with real survey data for production-grade insights.
- Linear model — captures linear relationships well but may miss complex
  interactions between features.
- Self-reported inputs are inherently subjective and not clinically validated.
- No temporal/longitudinal signal — each row is a single snapshot.

## 17. Future Improvements

- Swap in a real, ethically-sourced mental health survey dataset.
- Add SHAP-based per-prediction explanations for non-linear models.
- Add a classification variant (e.g., risk tiers) if a labeled dataset supports it.
- Add user authentication and persistent prediction history.
- A/B test additional engineered features (e.g., weekend vs weekday habits).
